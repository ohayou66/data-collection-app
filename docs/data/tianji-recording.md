# 天机录制、后台保存与上传

[文档目录](../README.md) · [项目首页](../../README.md)

操作与按键见[天机指南](../usage/tianji.md)。平台登录、存储模式和公共目录说明见[数据说明](recording.md)。

## 录制范围与保存位置

数据在 App 内 `teleop_control/runtime/tianji/episodes/<回合>/` 保存，遥操作采集默认不限时（`max_seconds=0`），按 B/Y 结束并保存；取消采集层 150 ms 反馈新鲜度、300 ms 遥测静默、相机事件等待和相机出帧间隔的自动中止。延迟、缺帧及对齐缺项保留在质量报告中，不补造数据；真实设备故障、连接关闭、写入失败和磁盘不足仍会停止采集。不限时需要先按[控制器升级说明](../maintenance/tianji-camera.md#控制器更新)升级相机服务，旧服务仍可预览，但 App 会拒绝开始不限时录制并提示升级。按本轮实际连接的相机录制，支持仅有两只腕部相机；命名为 `head_color`（usb-1）、`right_color`（usb-2）、`left_color`（usb-4）。

## 连续流与后台保存

相机预览与录制共享同一条连续流，开始录制时订阅当前流并排除开始之前的帧，不重新打开 USB 相机。控制器 2.5.0 支持在原视频流中结束采集分段并核对帧计数和时钟对齐，预览与下一轮继续复用；旧控制器按停止、清理、重新取流的兼容流程处理，避免双客户端抢占。控制器报告审计故障（如 `dmesg_sha256`）时会显示原因，不绕过锁定。

本机后台保存队列位于 `teleop_control/runtime/tianji/save-queue`，完成数据进入 `teleop_control/runtime/tianji/episodes`。完成入队后可准备下一轮，退出 App 不终止后台保存；失败保留缓存并重试，不完整数据不上传。

Tianji 控制器每路相机的 8 帧发送队列满时，跳过新到的帧并继续取流，保留已排队和正在发送的帧；不覆盖发送中的内存、不补帧、不改原始序号或时间戳。结束记录包含每路累计跳过数量、首末序号及时间范围（范围内不表示每帧均丢失）；这些累计量覆盖整个预览/采集流。采集质量标记会排除明确发生在按 A 之前的损失，跨越边界的损失保守标记为不合格。此行为需更新控制器相机服务；实际断连、损坏帧和发送超时仍按故障处理。

## 记录内容与单臂上传

本机保存实际双臂关节、双夹爪反馈、夹爪对齐来源与误差、实际 SDK 接受的关节指令以及相机索引；`record/actions.jsonl` 与 bundles 中的 action 来自命令，不以关节反馈伪造。元数据同步新版运动学/坐标映射、本轮实际相机清单、各路原生分辨率与硬件亮度读回值。上传时按所选臂筛选临时 tar 内的关节、夹爪、动作和对齐记录。新单臂回合携带 `upload_camera_policy=selected_wrist_optional_head_v1`，同步筛选相机文件、帧索引、相机映射及平台视频信息；保留所选图像与原始时间戳，本机完整原始文件不改写。无该标记的旧回合仍按原策略上传全部已录制相机。元数据分别记录实际控制范围 `controlled_sides` 和上传范围 `upload_sides`；已上传回合不自动重传，旧回合沿用原有控制范围与存档格式。

## 完成标记、上传与失败处理

B/Y 正常结束后，写完索引、时钟对齐、元数据和校验结果，最后才创建 ready 标记。复用 G2 的上传队列：登记导入批次 → 申请上传地址 → 上传单回合 tar → 注册 Tianji Episode → 保存上传回执；同账号登录时失败自动重试、重开 App 后继续、成功后不重复上传。操作栏在“检查设备”左侧显示本次完成的 Episode 数量和采集状态；采集或上传失败时显示原因。

单纯的缺帧、延迟或时间对齐缺项允许正常收尾并上传，质量报告不标为合格；真实反馈故障、相机异常、磁盘空间不足等中断会保留不完整回合，但不加入自动上传队列；完整回合的频率/标定质量结论也会保存在元数据中。停止遥操作时仍在录制的回合按中断处理，应先按 B 完成本段。
