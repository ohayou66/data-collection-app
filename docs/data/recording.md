# 数据保存、格式与平台上传

[文档目录](../README.md) · [项目首页](../../README.md)

## 遥操作与 UMI 数据保存

从源码启动 App 时，采集服务会在本仓库内自动创建原始回合目录。

| 设备 | 目录 |
| --- | --- |
| 天机 Marvin M6 | `data/tianji/` |
| 乐聚 KUAVO 5-W | `data/kuavo/` |
| 智元 G2 | `data/g2/` |
| UMI | `data/umi/rosbags/<任务>/<回合>/` |

- 在登录页的「启动模式」下拉框选择本次采集的数据保存方式。
- **默认（仅保存原始数据）**。点击「进入采集」，无需平台或账号。结束回合后原始文件保存在对应设备目录，以后选择上传模式也不会补传这些回合。
- **上传本机平台**。先启动本机数据平台 Docker，并在 App 内登录。原始文件写完后，App 最后写入 `.data-platform-ready.json`，用采集账号的 token 向 `POST /uploads/local-episodes` 提交固定 UUID 和相对于 `data/` 的回合目录。HTTP 201 表示已提交平台。网络中断时 App 保留原目录并重试登记。
- 平台通过只读挂载读取原始数据，负责 LeRobot 转换、时间轴和缺帧检查、可视化缓存。当前转换器支持天机 schema 2（弧度）与 UMI 的 MCAP/MP4 回合。G2、乐聚可以登记，转换支持取决于平台。转换进度、失败重试、源文件下载和删除 LeRobot 后的重新转换均在平台「格式转换」页操作。保留已登记目录的原位置和文件内容，平台后续会再次读取它们。
- 后端无界面启动时也默认仅本地保存。使用 `./start-app.sh --backend-only --storage-mode local-platform` 可显式开启本机上传。平台默认使用 `http://127.0.0.1:8000`，可通过 `UMI_LOCAL_API_URL` 和 `UMI_LOCAL_WEB_URL` 设置其他本机端口。
- UMI 在录制开始时固定采集账号与启动模式。采集和本地视频整理完成后，上传模式提交 `source: "umi"`、固定 UUID 和 `umi/rosbags/<任务>/<回合>`。平台读取原生 `meta.json` 和回合文件，负责 LeRobot 转换。默认模式、放弃的回合、整理中的回合均不会被自动登记。以前保存在 `~/galaxis_data/rosbags/` 等位置的录制保留在原处。

## UMI 录制就绪

Tianji 与 UMI 的默认单轮采集均不限时，由操作者结束。UMI 已删除 90 秒警告和
120 秒自动停止；相机、编码器及 PICO 时间间隔/帧率检查仅保留诊断，TF 不再按
年龄中断录制。实际追踪无效、分辨率错误等内容检查仍有效。UMI 转码时，低帧率和
长帧间隔记入质量警告，允许保存；时间戳重复/回退及文件损坏仍报错。
停止并重新启动 UMI 采集服务后重新生成配置。天机 PC 修改需重启 App；控制器端
相机停顿策略需由操作者运行 `python3 scripts/update_tianji_camera_stream.py` 更新，
只更新本地源码不会改变已安装服务。本次修改没有连接或更新真实设备。
启动连接、首次通道就绪、停止清理和网络请求的超时用于报告操作失败，不属于单轮
采集时长上限，仍保留；机器人运动控制的失联、急停及电机故障保护保持原有行为。

开始回合时，录制器先等待当前配置启用的相机、PICO 位姿和夹爪消息实际写入
MCAP，才报告录制成功并开始回合计时。仅创建进程、相机预览正常或已有
文件头不会视为就绪；单臂模式不等待关闭侧，低频状态/静态标定话题不阻塞启动。
最多等待 8 秒；超时会说明缺少的通道，进程退出会报告退出码，失败回合不进入
保存和上传流程，未完成文件不会提交平台。不会改写已有回合。

本次更新新增 Python `mcap>=1.2.2,<2` 依赖；从源码更新的电脑需先在
`umi_collection/vendor/galaxis` 中运行 `docker compose build galaxis_core_builder`，
再退出并重新启动 UMI 采集服务。录制开始请求允许等待就绪及失败清理，不应
在等待过程中重复按开始。其他电脑使用新镜像/重新打包的 App。

## UMI 保存与平台导入导出

新 UMI 回合的相机画面保存为 H.264 MP4，不使用 HDF5。停止回合后先从临时
MCAP 转换，逐帧校验视频并核对所有非图像消息，再发布完成标记和清理原始大包。
`media/left.mp4`、`right.mp4`、`center.mp4` 对应实际启用的相机；
`media/signals.mcap` 无损保留关节、位姿等消息，`media/video-manifest.json`
保留每帧原始 ROS 时间戳、消息头、序号和文件校验值。视频默认采用 CRF 12 有损编码，
保持源分辨率和帧数。中断或转换失败时保留原包，重新启动采集服务后重试未完成保存。
平台需要同时部署本次 worker 和网页导入代码；原始文件下载包含 MP4、传感器数据及
时间戳清单，转换后的预览、曲线和 LeRobot 导出保持原接口。

旧回合继续兼容 ROS 2 rosbag（MCAP）。旧目录包含单个
`<回合>_0.mcap`、`metadata.yaml` 和 `meta.json`；图像、位姿、夹爪、标定、
按键和时间戳按现有录制话题保存在 MCAP 内。双臂/单臂硬件配置继续决定录制话题。

历史直传流程中，录制器停止并刷盘、验证回合元数据后，原子写入 `meta.json`。上传器只扫描
已收尾的回合，并检查 MCAP 首尾标记及元数据引用。平台登记采用
`source=rosbag`、`format=rosbag`，存储键为 `raw/mcap/metadata/meta`，由平台
现有 rosbag 转换任务生成预览、曲线和可导出的数据。原始数据下载包含上述三个文件。
失败可重试，成功登记保留回执避免重复；账号切换后等待原采集账号重新登录。

历史 HDF5 文件保留，不会批量改写；旧进程恢复时仍保留 HDF5 收尾保护。
源码更新后重新启动 App 和 UMI 采集服务；已安装的 `.deb` 需要重新构建包含
更新录制器的 UMI 镜像并打包安装，新源码不会自动替换旧安装包中的镜像。

历史 HDF5 的独立检查工具见 [HDF5 数据检查](hdf5-quality.md)。
