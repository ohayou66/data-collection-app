## 乐聚 KUAVO 5-W

遥操作配置增加“乐聚 KUAVO 5-W”，桌面和网页均使用独立页面与 `/kuavo` 接口。进入页面、轮询状态不会连接机器人；“检查设备”查询原网络服务与准备记录，并核验 PICO USB、Galaxis VR 应用及持续更新的头显和双手柄输入。已授权且核验为 PICO 后准备缺失的应用和 USB 隧道，保留已运行应用及其发送开关。点击“检查设备”还会按需启动厂家主控、初始化，并检查左右夹爪；缺少准备参数时调用原夹爪准备接口并核对读回，不会开始遥操作。头显检查在独立子进程中进行，原生 SDK 异常不会导致机器人状态检查进程崩溃。

源码已放在 `teleop_control/vendor/kuavo_runtime`，同步自桌面 Teleoperation 的 2026-10-26 冻结 PC 快照 `20261026T033124Z-9c54dd5b1c6b`；174 个文件按原清单校验后复制，不使用外部源码目录或软链接，移动参考工程不影响 App 加载乐聚代码。独立 worker 防止 KUAVO 与 G2 的同名 Python 包冲突。真实遥操只由操作者点击开始并确认后启动；结束请求使用原版协作退出，不杀机器人主控。原服务仍核验版本、会话所有权和实时反馈。

- 原按键：Grip 控同侧手臂；Trigger 独立控夹爪（0 张开、1 闭合）；双臂模式松开两侧 Grip/Trigger 后，左 Y 请求回初始姿态。支持 `return_y_toggle_v1` 的服务再按 Y 取消，旧版仍使用右 B；单臂禁用 Y。A/X 不映射天机采集功能。
- 新版服务通过“机器人参数”读取并保存左右臂各自的倍率、速度、加速度，以及左右夹爪开合目标、速度、加速度，共 14 项。字段范围和组合由当前服务校验；旧版服务保留本地“其它参数”方式。回位姿态仍由机器人端决定。
- 网络默认“本电脑网络”，使用安装 App 的这台电脑的网卡和路由，不依赖原电脑的 `kuavons`。页面不再提供网络方式选择，所有操作固定使用本电脑网络。旧 `kuavons` 仅保留底层接口兼容，不从页面启用。“机器人连接”入口暂从页面移除；已有连接配置继续使用，换机需通过保留的 `/kuavo/connection` 接口配置服务 IP、端口、证书指纹及 token。保存只写本地 0600 配置，不连接设备、不自动改网卡。电脑必须能够通过所选网络到达机器人服务地址；PICO 接收服务、SDK 和 USB 连接仍需准备。
- “启动主控”“厂家初始化”“读取夹爪状态”“准备夹爪”仅在用户明确点击时调用原准备接口。启动主控仍要求确认电机编号；App 按用户要求默认传入接受共享 CAN 总线条件，不再显示勾选项；原配置的未验证标记保持原样。准备结果不明时先查询，不能当作成功，也不要重复发初始化。
- 本地自动记录每次会话，目录 `teleop_control/runtime/kuavo/episodes/<时间_编号>`：`events.jsonl` 为原客户端输入/机器人诊断回执，`meta.json` 为任务、结束时间和退出报告。它是过程日志，不声称是同步图像数据集，也不会被天机上传器扫描。

当前预留：相机同步图像录制；关节微调与独立无头显回位（原网络接口未开放，保留会话内 Y/B）；平台格式转换及上传（本次暂略）。这些功能在页面有说明，不使用天机模型或模拟数据替代。

当前机器的连接配置与 token 已复制到 App 内 `teleop_control/runtime/kuavo/connection.json`、`token`，仅将 token 路径改为相对当前配置目录。未复制机器人服务端私钥。配置和 token 必须为 0600，Git/安装包排除 runtime；换机通过保留的连接配置接口保存对应凭据，不能把密钥放进公共安装包。接口不返回已存密钥。可用 `KUAVO_PYTHON` 指定已装 PICO SDK 的 Python；默认复用 App 机器人运行环境。

初始接入以离线验证为主；2026-10-23 已完成本机 PICO USB、头显唤醒和双手柄持续输入验证，并验证本机 VR 接收服务恢复流程。未启动机器人实机服务或实际遥操。重新打开 App 后加载修改；完整硬件验收由现场操作者进行。

旧版服务的乐聚页面 01 提供双臂 / 左臂 / 右臂选择、电脑端位移倍率（0.1–1，默认 1 保持原值），以及“其他参数”中的左右达妙夹爪备份参数。单臂通过原 XR 适配器的输入副本屏蔽另一侧 Grip/Trigger；原服务仍负责动作与保护。单臂禁用会同时操作双臂的 Y 回位，右 B 取消保持有效。运行中禁止更改模式及倍率。位移倍率、手臂速度和规划加速度均可编辑，修改后自动持久化；当前协议仍只支持手臂速度 0.7 rad/s、规划加速度 5 rad/s²，其他保存值标记待支持并阻止启动。夹爪编辑说明见下方，保存不代表已下发。

02 对齐为机器人、Galaxis VR、Pico 设备三类。PICO 检查 USB 授权、应用进程和数据隧道；Galaxis VR 必须收到有效姿态和持续递增的时间戳，SDK 安装不等于输入在线。空闲时显示最近检查结果，会话中使用实时输入状态，断流及时降级。检查自动准备已核验 PICO 的应用和 63901 USB 通道；应用缺失时仅安装 App 内 APK，不覆盖已安装版本，已运行时不强制重启。USB 和应用就绪但无有效输入时，复用天机的本机 XR 接收服务管理器恢复一次，再用新 SDK 实例验证。正常输入不会触发头显重启，不修改手柄映射；主控准备使用下方明确的检查按钮流程。检查受已有跨机器人空闲约束保护。

`teleop_control/assets/kuavo/full_robot.urdf` 与正式版本控制模型 SHA256 一致，`reference.json` 保存备份参数来源及散列；运行不读取桌面备份。页面使用官方 v63 网格绘制可旋转/缩放的实体模型，保持原 URDF 关节位置、转轴和角度单位。检查连接后启动独立只读姿态订阅，校验 v63 版本、URDF 散列及 20 个关节的顺序，读取真实身体、双臂和头部关节角；会话内的 `control_trace` / `ik_trace` 实测 `feedback_rad` 作为双臂反馈后备，不使用控制目标。只读连接断开、传感器时间戳停止递增或数据过期会显示过期，不用心跳刷新姿态有效期。相机采用头部主相机左侧放大、左右相机右侧上下排列的三个固定区域。

乐聚姿态外观来自 [LejuRobotics 官方 v63 资源](https://github.com/LejuRobotics/kuavo-ros-opensource/tree/ba5ae219d86076c587e5973c44f5f645ca874a95/src/kuavo_assets/models/biped_s63)，参照用户提供的“产品介绍 / 轮臂产品”图纸。29 个网格精简后存于 `public/kuavo-model.json`（约 3.5 MB），许可证随附 `public/kuavo-model.LICENSE`。`teleop_control/assets/kuavo/visual-manifest.json` 记录固定提交、每个原始文件散列、精简前后面数及尺寸边界变化。只作为显示资产，原控制 URDF 与 vendor 控制代码保持不变，不会从网页下载模型或连接实机。

重建显示资源可运行 `scripts/build_kuavo_model.py <官方文件目录> <GitHub tree JSON>`，构建时使用临时依赖 `fast-simplification==0.1.13`；应用运行不依赖此库。精简后边界变化超过 5 mm 的部件自动保留源网格，防止不规则 CAD 三角面产生尖刺。Qt 与网页共用既有三维显示能力；KUAVO 按关节名直接使用实测弧度值，天机保留角度转换与夹爪映射。没有实时反馈时显示参考或最后姿态并提示不可用/过期；夹爪从会话状态中的真实电机反馈计算开合比例，再驱动显示模型的左右夹指；未收到反馈时保留半开参考，停止或反馈过期时保留最后姿态，不以扳机或目标值模拟动作。

### 乐聚客户端与机器人参数更新（2026-10-26）

“检查设备”现在也是主控准备入口：Qt 和网页点击时明确提交 `prepare_controller=true`、`prepare_grippers=true`、`confirm_motion=true`、`motor_ids_confirmed=true`，按当前左夹爪 8、右夹爪 1 的配置准备；不再要求终端命令；按用户要求移除按钮下方的三行常驻说明。仅打开页面、轮询状态、保存参数均不会启动主控；不带准备许可的 API 检查保持只读主控状态的兼容行为。

流程复用 App 内 `vendor/kuavo_runtime` 的原版 `PreparationWizard.controller()`，不运行完整遥操作向导：`not_started` 请求一次 start，`awaiting_confirmation` 请求一次 initialize，`starting/preparing` 等待状态，`ready` 跳过已完成阶段。已有会话占用、其它入口更换服务/参数/主控进程、未知状态及超时均终止本轮，不重启或接管已有主控。每个等待阶段最多 120 秒；后台整体检查上限 900 秒，界面持续显示阶段进度。主控及夹爪检查通过后，界面请求 `prepare_session=true`，继续建立真实遥操作会话、完成计算进程与 READY 校验；App 输入门控在此期间屏蔽所有按键、扳机、Grip 和摇杆，只发送中立输入。收到新鲜机器人状态、两侧夹爪 READY、新鲜且已释放的手柄输入后才开放开始按钮。操作者点击开始仅激活这一会话，不重建计算进程；尚未释放的输入仍等待释放，准备失败/退出/过期不允许开始。准备期间允许修改操作范围及参数；范围在开始时传给输入门控，参数保存则自动取消旧准备、等待本会话释放、按原版本提交修改并核对回读，再用最新参数重新准备。运行前可返回配置，`POST /kuavo/cancel-preparation` 取消本 App 的检查/待机并返回空闲；返回或再次取消会使旧的自动恢复任务失效。已发出的厂家准备请求保留回执编号，下次只查询原结果。界面提交 `require_prepared=true`，不允许绕过检查直接启动；旧 API 调用保留显式直接启动兼容行为。

新版服务以经过完整性与身份校验的在线参数契约为准，准备流程不再拿旧版本地夹爪 JSON 的整份哈希拦截新版运行配置；仍固定服务、安装及契约版本，变化即终止。旧版无在线参数的服务继续核对本地配置哈希，不删除或迁移旧文件。

主控就绪后复用同一向导的夹爪检查与准备：先 `grippers_inspect`，两侧均通过检查且仅需准备时才调用一次 `grippers_prepare`；机器人端核对电机身份、禁用状态、位置和配置，只设置易失的 mode 4 与 watchdog 4000，并独立读回确认，不写 Flash，不绕过标定或自动使能。任一侧超时、位置异常、配置不匹配、读回失败或结果不明均停止，界面禁止开始。已准备则跳过写入。恢复丢失的准备回执后若仍未就绪，本轮不重复写入。此步骤不修改用户保存的速度、加速度、位移倍率或开合目标。

准备请求在发送前写入 App 内 `teleop_control/runtime/kuavo/preparation-receipts`（目录 0700、文件 0600），绑定服务和安装身份。回复丢失时保存原请求编号，下次检查先查询原结果，不重复发送。App/后台退出后不再请求下一阶段；已经发出的机器人准备动作不会因此被撤回。此流程不调用桌面 Teleoperation 的脚本，不依赖 `/home/yuan` 或参考目录路径，不复制或部署机器人主控；通过现有认证网络接口调用机器人上已安装的启动器。

“服务在线”与“厂家主控就绪”分别判断：服务的 `ready_to_start` 仅代表可接收会话，不能代替硬件准备。执行 worker 在创建头显输入、打开遥操会话前仍会只读核验 `/robot_version=63`、`/hardware/is_ready=1` 和外部 MPC 状态；未就绪时禁止发送手柄控制。

默认模式为“双臂”，另有左臂、右臂和“双臂＋底盘”。默认双臂及单臂均在发送前屏蔽两只摇杆与 X 键，联合服务也不能通过这些模式解锁底盘；单臂额外屏蔽另一侧 Grip/Trigger；经用户明确选择，所有模式的 Y 都执行双臂及夹爪回位，再按 Y 取消。只有“双臂＋底盘”转发底盘摇杆，启动时再次核验联合服务能力；进入运行并保持新鲜中立输入 100 ms，收到新鲜的已锁定且停止反馈后，App 仅执行一次原协议底盘准入握手，不再转发物理 X。左摇杆平移、右摇杆左右转向。超时或故障不自动重新解锁，完成或取消 Y 回位后需摇杆回中重新准入。沿用上游底盘保护和会话退出流程。视频本次未接入；没有切换或部署机器人服务。

新版服务下，Qt 和网页主界面的位移倍率、速度、加速度直接显示机器人参数范围，修改后约 350 ms 自动提交到选中侧；双臂和双臂＋底盘修改对应的左右两侧字段。左右值不同时显示左侧值及提示，只提交用户改动的项，避免覆盖其它参数。乐聚操作区不再显示保存说明、SSH 姿态错误、准备过程文字或其它按钮消息横幅；原始诊断和后端校验仍保留。模式顺序为“双臂、双臂＋底盘、左臂、右臂”。

“其它参数”与天机使用相同的紧凑双列输入框、单位和“确认 / 取消”按钮，显示 8 项夹爪参数；双臂位移倍率、速度和加速度继续在主界面按左右臂选择分别设置；确认时后台先校验修改、再保存并核对读回，取消不提交。运行中禁止改参。旧版服务继续显示其本地待应用限制，不伪称已下发。

`POST /kuavo/session-settings` 支持 `read`、`preview`、`apply`、`reset`。写入带最初读取的 revision、service_instance_id、installation_sha256；轮询不会暗中更新正在编辑的版本。服务先校验范围和参数组合，再保存；回读快照必须与保存回执一致，改动字段必须等于请求值。冲突、超时、回读不一致均不显示已应用，也不自动重发。主界面保存失败后重新检查设备，再修改；保存期间不能开始或换操作范围。

开始时固定已回读的参数版本和散列，重新选择服务后再次核验；官方客户端还核对实际工作进程 READY 中的左右臂倍率、速度、加速度、夹爪参数及参数散列，匹配后才发送手柄输入。电脑端倍率固定 1，不重复放大。日志记录本轮参数；标定、电机编号、厂家保护和其它机器人路径保持不变。

姿态跟随在检查后即可工作，不要求开始遥操作。现有机器人管理服务没有空闲关节流，因此使用 App 内复制的参考代码，通过 SSH 运行仅订阅 `/sensors_data_raw` 的临时程序，不上传文件、不调用控制服务、不启停主控。默认主机与 connection.json 一致，用户 `lab`，ROS 环境 `/home/lab/kuavo-ros-control/devel/setup.bash`。需要电脑预先信任该主机并有非交互 SSH 认证；缺少授权时界面显示只读姿态不可用，不自动接受主机密钥。可在 App 内 `teleop_control/runtime/kuavo/readonly.json` 配置，例如：

```json
{"user":"lab","ros_setup":"/home/lab/kuavo-ros-control/devel/setup.bash"}
```

可选 `control_path` 为已有、已认证 SSH 会话的绝对 socket 路径；不填时使用本机标准 SSH 密钥/agent。退出 App 或更换连接只关闭本 App 的只读订阅。连接故障后点击检查设备重建，不重启机器人服务。主控未输出传感器数据时只报告等待数据。

离线验证：乐聚及 Qt 相关测试 122 项通过（含检查按钮准备流程、丢失回复恢复、退出后不继续下一阶段及迁移到独立 App 目录）；天机、G2、UMI、打包和导航回归 239 项通过、1 项跳过；TypeScript 类型检查及网页构建通过。

### 旧版服务：换机与本地夹爪参数（2026-10-23）

“任何安装本 App 的电脑”是使用本机网络和随 App 提供的代码，不表示任意操作系统或缺少驱动的电脑都即装即用。需要 App 支持的系统/架构、可达机器人的网络、该机器人的连接凭据，以及与 Python 环境匹配的 PICO SDK 和接收服务。完整机器人运行环境可复用 App 的 XR 依赖；源码运行可通过 `KUAVO_PYTHON` 指定环境。当前没有修改用户网卡或实机服务，也没有重新生成安装包。
