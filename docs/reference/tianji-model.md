# 天机模型、坐标与控制

[文档目录](../README.md) · [项目首页](../../README.md)

适用于模型与控制维护。日常操作见[天机指南](../usage/tianji.md)；离线回归、历史现场测量和当前实机验收各有不同范围。

## 坐标与模型同步

坐标修正（`vendor_cad_same_facing_v2`）：操作者在机器人背后同向，统一 +X 前、+Y 左、+Z 上。活动模型使用厂家原始臂几何和 `mount_orientation=cad`，URDF 为 `marvin_left_with_gripper.urdf` / `marvin_right_with_gripper.urdf`；废止 `front_back_mirror_v1` 和未经实测的 Y 轴 180° 安装补偿。后者会同时翻转前后和上下，几何镜像还会改变转腕轴关系；两者均不能由“站在背后”推出。硬件编码器角度、零位与左右臂身份保持厂家定义，零位是向两侧水平伸直。FK、IK、雅可比、TCP 和碰撞模型使用同一安装变换，手柄位置与姿态使用同一个右手旋转映射。运行 `python3 scripts/sync_tianji_coordinates.py` 从活动 URDF/安装配置同步 Qt、Web 和 TCP 查看器共用的预览；控制进程在连接机器人前检查预览的安装、关节轴和 TCP，拒绝过期导出。采集元数据与遥测保存坐标版本和会话基准，旧回合不改写。

PICO 原生追踪输入采用 +X 右、+Y 上、+Z 后（前方为 −Z），位置单位米、四元数顺序 xyzw。当前 Unity 客户端直接发送 PXR 原生预测位姿，不能套用 Unity 场景的 +Z 前约定。头显水平基准与追踪基准对齐时，映射为机器人世界 `(X,Y,Z)=(-z,-x,y)`；其它朝向先按首次接管的头显水平朝向转换。手柄局部轴随手柄姿态旋转，不能把它与固定追踪轴或 TCP 轴等同。OpenXR 基准定义见 https://registry.khronos.org/OpenXR/specs/1.1/man/html/XR_REFERENCE_SPACE_TYPE_LOCAL.html 。此处核对的是代码与协议，未替代当前设备实测。

## TCP 定义

遥操作 TCP 为每只夹爪两侧固定转轴所在平面与电机轴线的交点，沿法兰 +Z 方向距安装面中心约 142.226 mm；不随夹指开合变化。左右臂分别使用 URDF 的 `grasp_center_L/R`，控制与显示同步。该位置为 CAD 名义值，更新后须重启 App 加载。

2026-11-12：左右手 TCP 的 +Y、+Z 同时反向（绕 TCP 自身 +X 旋转 180°）；原点与 +X 不变。两侧 `grasp_center_fixed_L/R` 均使用 `rpy=[π,-π/2,-π/4]`，夹爪安装与实体外观不变。通过 `查看TCP仿真.sh` 查看模型原点 O、TCP 原点 P 及各自的正方向箭头。

遥操接管锚点、目标位姿、FK、IK 和记录使用同一 URDF TCP。仅重定义 TCP 朝向时，目标与工具同时右乘 `diag(1,-1,-1,1)`，逆解后实际法兰目标保持一致；不额外反转 PICO 的 Y/Z 输入。`tests/test_tianji_tcp_reframe.py` 覆盖左右手、两种头显朝向、六向平移及三轴正反旋转，并比较修正前后的关节指令。

## 逆运动学与控制模式

整臂逆解（`mirrored_reference_local_ik_v7`）：按 `test-teleop/retarget.py` 的 OpenXR → 水平操作者坐标 → 机器人坐标链路计算位置增量和旋转共轭，36 组参考输出覆盖双手、头显朝向和三轴动作。双臂共享首次接管的水平朝向，松握把和转头不重定义另一臂方向。逆解借鉴 `test-teleop/ik.py` 的已接受关节指令积分：普通位形从上一条成功发送的关节指令做一次阻尼微分修正，手柄换向时丢弃尚未到达的旧优化姿态；接近任务奇异性时，按雅可比条件连续保留局部延续解，并增加至最多四次数值修正，避免冗余关节因微小误差重新选姿态。保留每次握把会话有限的统一姿态引导预算和固定目标的有限求解，避免举高停顿、静止抖动或不可达目标持续转腕。左臂通过厂家验证的完整镜像使用独立右臂求解实例；位置、旋转、轴向角速度、雅可比、TCP 和耦合腕部限位一起映射，URDF、硬件编码器和水平零位保持厂家定义。遥操作 J4 上限为 −5°，高于该值时只允许向内回退；手动控制和复位采用各自的限位规则。速度、加速度和刹停约束对全部关节一致，无固定末端速度上限。参考工程使用 G2 硬件，其 URDF、关节编号和限位不适用于天机，因此只移植坐标及连续增量计算方法，仍使用已核对的天机厂家模型与硬件接口。离线测试不能替代实机装配、编码器标定及跟随验证。

天机遥操作、手动移动和复位均恢复改阻抗前的位置控制流程（`state=1`），发送关节位置目标；不调用 PD 前馈接口，不读取或写入 `JointPIDCtlType`，不配置关节阻抗增益、不保存控制器参数。目标更新频率仍为 100 Hz，原有关节限位、速度/加速度、碰撞和失联保护保持不变，夹爪协议不变。回退 App 代码不会清除控制器已保留的故障或恢复其运行时参数，仍须通过正常停机和预检后才能启动。

## 复位与碰撞边界

故障后回零：选择“零点（默认）”并点击复位，可从 idle/error 状态独立启动，无需 VR/相机预检。按厂家平台的清错→双臂下使能确认→当前反馈保持点→位置模式顺序执行，再逐臂低速将七关节直接回零并下使能，不经过逆运动学。若同臂非相邻连杆的包围盒仍分离、但已进入 15 mm 余量区，优先恢复该臂；预检和运动中均要求间距从当前值恢复，不得继续挤近（反馈容差 0.1 mm），退回余量区外后恢复完整余量。预检的间距状态与实时反馈独立，避免用未来路径的间距误拒绝当前位置。其它已纳入当前模型的连杆对、工具和环境障碍仍受原碰撞检查约束，真正重叠的包围盒不允许豁免。新增末端全 CAD 网格检查未启用，不应据此认为外接相机支架已被完整覆盖。流程可取消，状态会显示当前阶段及间距恢复记录。恢复路径使用厂家硬限位，允许从普通遥操的安全余量边界返回，不再被 URDF 的角度舍入误差误拒绝。真实越过厂家硬限位、持续急停/伺服故障、反馈停止和路径碰撞仍会中止。清错接口的 C 返回类型为 void，以新实时反馈确认结果，不把返回值当作成功标志。

本次合并按上游模型与 TCP 定义运行，暂不启用本地新增的末端全 CAD 网格碰撞检查；碰撞行为沿用上游实现。相机和支架不能视为已经由该新增检查覆盖。相关本地实现保存在合并前提交 `2d832c9`，重新启用前须适配上游法兰资源并重新生成、验证碰撞模型。

## 实测安装标定

验证边界：厂家 FK/URDF/雅可比交叉检查、六向平移及三轴转动回归只能证明软件链路一致，不能证明真实装配、编码器标定或现场朝向。若与实物仍不符，使用 `PYTHONPATH=teleop_control/vendor/tianji/teleop python3 -m marvin_teleop.installation init --file /tmp/tianji-measurements.json` 建立测量文件；测量所选夹爪 TCP（不是裸法兰），每臂需要至少 3 个分布充分的拟合姿态和 1 个独立检查姿态，再通过实测安装旋转标定，不叠加轴反号。该工具 `init`/`fit` 离线运行，`capture` 只读关节并接收人工测量，不发送运动指令。

## 源码与验证范围

所需 SDK、运动学配置及碰撞模型仅保留在 `teleop_control/vendor/tianji`，运行不依赖桌面的原 SDK 目录；来源和适配点见其中 `UPSTREAM.json`。已同步此次更新的夹爪标定、加速度限制、控制周期和按键定义，也同步既有相机客户端的新色彩转换及恢复接口。仅在没有录制、控制器明确标记故障可恢复并通过清理及审计检查时，有限重试下一条预览流；遥操已启动但尚未开始某一轮录制不再阻止相机预览重连。机器人/XR 的急停、失联、硬限位和碰撞保护仍独立生效。不重置 USB 主控，不把失败采集恢复成成功。
